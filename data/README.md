# Data

Three layers, and only the first one is in git.

| Layer | Path | Rule |
|---|---|---|
| demo subset | `data/demo/` | a few hundred rows, enough to run the pipeline end to end; safe to publish |
| full data | external (Zenodo / institutional repository) | never in git; declared in `MANIFEST.json` |
| derived artefacts | `outputs/` | regenerated by the pipeline, never committed |

## Why not just commit the data

- GitHub rejects files over 100 MB and warns above 50 MB;
- git keeps every version forever, so one 200 MB revision doubles the repo;
- a repository is a *code* artefact; a data set needs its own DOI, its own
  version and its own licence — that is what a data repository is for.

## How a reader gets the full data

```bash
python scripts/download_data.py          # downloads + verifies sha256
```

`MANIFEST.json` is the contract:

```json
{
  "doi": "10.5281/zenodo.XXXXXXX",
  "files": [
    {
      "name": "data_point_pd.pkl",
      "url": "https://zenodo.org/records/XXXXXXX/files/data_point_pd.pkl",
      "sha256": "<64 hex chars>",
      "size_bytes": 12345678,
      "description": "AFM force curves, one row per pixel; features f1..f6, label M0/M1/M2"
    }
  ]
}
```

Rules for the manifest:

1. one entry per file, `sha256` mandatory (compute with
   `python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" file`);
2. `url` must be a permanent link (Zenodo/Figshare/institutional DOI), not a
   personal drive link that expires;
3. `description` says what a row is and what the columns mean — this is the part
   reviewers actually read.

## Licensing

Third-party data keep their original licence and are **not** relicensed by this
repository. Record the licence of each external file in `MANIFEST.json` under a
`license` key when it is not your own.
